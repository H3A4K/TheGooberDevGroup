3. Purpose

The app is to redesign the restaurant's website to be more modern and follow traditional design principles. We will have a menu that will list all the items and a large description with a button to add to cart, an ordering page that will show a shorter description and ability to add to cart, and a cart that will allow the user to place their order with the restaurant.

There will also be an accounts system to allow users to see their previous orders. Customers will use the site to browse menu items, add items to their cart, select between pickup/delivery, create an account, apply promo codes for discounts, and place orders online. Clarence's Kitchen will use the site to present a more modern brand image of themselves and manage promotions through promo codes.

We have chosen to take on redesigning their site, as the current one is outdated and does not follow traditional design principles. Ometh would like a modern site to draw in more customers. We will also make the site responsive, so that customers can use either their phones or their computers to place an order, which is currently not supported properly on their current site.


4. Data Description

Table 1: User Accounts

We need this table to store the different customer's login details as well as any other information about their account. The information that will be stored is email, password, phone number, address and number of orders.

Fields: userid (number), email (text), password (text), phonenumber (text), address (text), ordersdone (number). Primary key will be accountId.

Field Type
accountId number
email text
password text
phonenumber text
address text
ordersdone number

Table 2: Products

We need this table to easily get a list of all the available products that the customer is able to order. The information that will be stored is product name, product description and price.

Fields: productid (number), productname (text), productdesc (text), productClass (text), price (float). Primary key will be productid.

Field Type
productId number
productName text
productDesc text
price float / Number
productClass text

Table 3: Orders

We need this table to get a list of all orders that were ordered, including past orders for order history. The information that will be stored is the account that ordered, the address to deliver to if its delivery, the date it was ordered, and whether the order has been fulfilled. The individual items in each order are stored in the OrderDetails table (see below), following proper database normalization principles (similar to the Northwind sample database on W3Schools).

Fields: orderId (number), accountId (number), orderDate (text), address (text), fulfilled (boolean). Primary key will be orderId. Foreign key accountId references User Accounts.

Field Type
orderId number
accountId number
orderDate text
address text
fulfilled boolean

Table 4: OrderDetails

This junction table links orders to the products they contain, rather than storing a list of items directly in the Orders table. Each row represents one product line in an order, with a quantity field. This follows the same pattern as the OrderDetails table in the Northwind sample database.

Fields: orderDetailId (number), orderId (number), productId (number), quantity (number). Primary key will be orderDetailId. Foreign key orderId references Orders, foreign key productId references Products.

Field Type
orderDetailId number
orderId number
productId number
quantity number

Table 5: PromoCodes

This table stores promotional codes and discounts that can be applied to orders. Promo codes are entered by the customer at checkout and validated against this table. When a valid promo code is applied, the discount is calculated and deducted from the order total in the cart before the order is placed. Admins can create, modify, and deactivate promo codes through the admin interface.

Fields: promoId (number), promoCode (text), discountType (text), discountValue (float), active (boolean), expiryDate (text). Primary key will be promoId. The discountType field is either "percent" or "amount", which determines how discountValue is applied (e.g. 15% off vs. $5 off).

Field Type
promoId number
promoCode text
discountType text ("percent" or "amount")
discountValue float / Number
active boolean
expiryDate text

Shopping Cart (localStorage)

The shopping cart will be managed client-side using the browser's localStorage. Cart data (product IDs and quantities) is stored as a JSON object in localStorage, so the cart persists across page navigations and browser sessions on the same device. When the user places an order, the cart contents are sent to the server, which creates the Order and OrderDetails entries in the database, and the cart is cleared from localStorage.


5. Functions Performed by the App

Customer Functions

  • Sign Up/Login Page
    • INSERT/UPDATE to database on signup
    • SELECT from database on login
  • Product/Ordering page
    • SELECT from database for products
  • Cart Page
    • Cart contents stored and managed in browser localStorage (client-side)
    • SELECT from PromoCodes table to validate and apply promo codes at checkout
    • INSERT into Orders and OrderDetails tables when placing an order
  • Search all keywords of items from entire website
    • SELECT from database for products
  • Pick up service
    • SELECT from database for pending orders
    • UPDATE to database to complete order

Admin Functions

  • Order Management
    • SELECT from Orders and OrderDetails tables to view all orders
    • UPDATE Orders table to mark orders as fulfilled
  • Product Management
    • INSERT into Products table to add new products
    • UPDATE Products table to modify existing products
    • DELETE from Products table to remove products
  • Promo Code Management
    • INSERT into PromoCodes table to create new promo codes
    • UPDATE PromoCodes table to modify or deactivate promo codes
    • SELECT from PromoCodes table to view all promo codes

9. Client Feedback

Based on the client’s feedback, we adjusted the project plan to make smooth, modern user interface, using the orange, black, and white colour scheme as Ometh said:
"Overall we just want something sleek and professional looking, like the one right now is kind of unprofessional looking you know?".

Ometh also requested that we add an accounts system as
"Having accounts would be super helpful as we could promote the restaurant through newsletters and promotions as well as keep track of customer data to see what menu items are trending."

Additionally, we will be displaying promotions on the menu as Ometh told us:
"We have lots of deals, especially buy 1 get 1 and student combos that we like to promote, so being able to see those on the menu page is really important."

The final change that Ometh requested was having a way to place orders directly with them, instead of redirecting them to UberEats, as they
"Currently have it setup so that it redirects customers to UberEats, but would like an actual in-store site".

All of these changes have already been reflected in the development plan outlined above.
